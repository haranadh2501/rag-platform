  ---
  Critical Issues

  1. File size limit inconsistency
  Three different limits appear:
  - Scope section: "9 MB per file (enforced client-side)"
  - n8n endpoint description (line 27): "Max 10 MB"
  - User messages table and ENV var: MAX_WHATSAPP_EPHEMERAL_UPLOAD_BYTES=9437184
  (exactly 9 MB)

  The limit must be stated once and consistently. Also — "client-side" is wrong
  terminology; enforcement happens server-side in FastAPI (there's no browser
  here).

  2. ingesting state can get permanently stuck
  Edge case table (line 436) says on n8n 5xx after retry: "status stays as-is."
  If the first upload fails, the session stays ingesting forever. The user has
  no way to recover except /end_session. The spec should define what state to
  revert to — awaiting_document if no docs were previously ingested, ready if
  this was an additional upload.

  3. No DB-level uniqueness constraint on user_id
  The spec enforces one session per user in application logic only. If there's a
  concurrency bug (two rapid /ephemeral_ingest commands), the DB will happily
  store two rows. Since rows are deleted on end, a simple UNIQUE INDEX on
  user_id is the safe guard.

  4. Concurrent upload race condition on total_chunks
  Edge case says "last writer wins on status (acceptable)" — but it's not just
  status. Two concurrent n8n ingest calls will both read total_chunks, add their
  own chunk_count, and write back. That's a classic lost update. The update
  should be total_chunks += chunk_count (atomic SQL increment), not a
  fetch-then-set.

  ---
  Design Gaps / Ambiguities

  5. expires_at is NULL at session creation
  start_session creates the row but the expires_at value only comes back from
  n8n's ingest response. The spec doesn't say what expires_at holds before the
  first ingest, or whether to update it on every subsequent ingest. Should be
  documented explicitly.

  6. Conversation history — who keeps it?
  The retrieve endpoint says "conversation_history optional (last 10 kept
  server-side)" but the retrieve_ephemeral() function signature passes history
  from FastAPI. It's ambiguous: does n8n maintain history server-side (then why
  send it?), or does FastAPI always load and send the last 10 chat_messages? One
  is correct; the spec uses both framings.

  7. file_validator.validate_upload referenced but never defined
  Line 434 in the Edge Cases table mentions this. It's not in the current
  codebase and not specified in this document. Either define it here or
  reference where it's coming from.

  8. MOCK_N8N extension not specified
  The testing checklist says "MOCK_N8N=true → all 3 ephemeral functions return
  mock responses" but the spec doesn't define what those mock responses look
  like or how n8n_client.py should detect MOCK_N8N and branch. The existing mock
  mechanism needs to be extended.

  9. Twilio media download authentication not specified
  handle_upload says "Download file from Twilio" but Twilio media URLs require
  HTTP Basic Auth using TWILIO_ACCOUNT_SID + TWILIO_AUTH_TOKEN. The spec doesn't
  mention this. An unauthenticated GET will return 401.

  10. Deleting the ephemeral conversation on end_session
  end_session is specified to "delete ephemeral conversation." The chat_messages
  table presumably has an FK to conversations. If chat_messages has ON DELETE 
  CASCADE, that's fine — but if not, the delete will fail. The spec needs to
  address the cascade chain.

  ---
  Module Ownership Conflict

  11. Alembic migration crosses into M2 territory
  Per CLAUDE.md, M2 owns backend/alembic/. Step 3 proposes
  backend/alembic/versions/0003_ephemeral_sessions.py. This needs explicit M2
  sign-off or the spec should note the coordination required.

  Also, the migration is named 0003_ — but the spec doesn't verify what 0001 and
  0002 are. If the actual migration history has a different numbering, this
  will conflict.

  ---
  Minor / Code Quality

  12. datetime.utcnow is deprecated
  Python 3.12 deprecated datetime.utcnow(). The ORM model should use
  datetime.now(timezone.utc) instead.

  13. Missing nullable=False on created_at in ORM
  SQL schema has created_at TIMESTAMP NOT NULL DEFAULT now() but the ORM model
  (line 255) doesn't set nullable=False, creating a schema/ORM mismatch.

  14. Branch name mismatch
  Spec header says Branch: feature/M4_webhook but the current branch is
  feature/ephemeral_integration_trial.

  15. RESET_COMMANDS referenced but not defined in spec
  Line 374 uses if query_lower in RESET_COMMANDS without defining what that set
  contains (/reset, /new, /clear?). Should be documented.

  16. Row return type vs ORM model
  get_active_session returns Row | None (raw SQLAlchemy row) but the ORM model
  EphemeralSession is defined. Inconsistency — pick one and use it throughout.

  implementation decisions, 1 ownership conflict requiring cross-team
  coordination, and 5 minor cleanup items. The most urgent to resolve before
