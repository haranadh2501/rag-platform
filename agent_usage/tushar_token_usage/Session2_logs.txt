  Component design

  1. types.py — MessageContext
  Dataclass exactly per spec §4 (request_id, user_id, tenant_id, source, query, 
  conversation_id, slack_channel, slack_thread_ts).

  2. pipeline_client.py
  - async def call_pipeline(payload: dict) -> dict
  - PIPELINE_URL = os.getenv("PIPELINE_URL", 
  "http://localhost:8000/webhooks/mock/pipeline"), timeout from
  os.getenv("PIPELINE_TIMEOUT_SECONDS", "120").
  - Returns parsed dict on 2xx; raises PipelineError on timeout/non-2xx.
  - Response contract = openapi ChatQueryResponse shape (your decision): answer,
  sources:[SourceChunk], follow_up_questions, optional
  conversation_id/faithfulness/metadata.

  3. message_service.py — async def process_message(ctx, db) -> dict
  Channel-agnostic; raises typed exceptions so each adapter maps them
  appropriately:
  - Step 2 — resolve identity (Slack: raw-SQL JOIN slack_workspace_map + users;
  web: already on ctx).
  - Step 3 — find/create conversation (raw SQL); on web conversation_id
  ownership mismatch → raise ConversationOwnershipError.
  - Step 4 — reset (/new /reset /clear) → delete + recreate + return
  confirmation, STOP.
  - Step 5 — load last 10 (raw SQL DESC LIMIT 10, reverse).
  - Step 6 — pipeline_client.call_pipeline(...); on failure raise PipelineError.
  - Step 7 — delivery: if source=="slack" → slack.post_reply(...); if "web" →
  return payload (no side-effect).
  - Step 8 — save user+assistant in one transaction (raw SQL), only on success.
  - Returns the response dict (web uses it; Slack ignores the return).

  4. webhooks.py (M4)
  - Replace the /slack/events stub: read raw body bytes → HMAC-SHA256 verify
  against settings.SLACK_SIGNING_SECRET (403 on fail) → url_verification echo →
  bot_id skip (200) → dedup INSERT ... ON CONFLICT DO NOTHING (rowcount 0 → 200)
  → field validation (missing → 200 + log) → ACK 200 → BackgroundTask(_run).
  - _run opens its own AsyncSessionLocal (the request's get_db session is closed
  post-response), builds MessageContext, calls process_message; catches
  PipelineError/identity errors → posts fallback or logs.
  - Add POST /mock/pipeline here (becomes /webhooks/mock/pipeline) returning the
  canned openapi-shaped response (mirror chat.py:14 MOCK_RESPONSE).
  - Leave /whatsapp and /n8n/ingestion-status stubs untouched (out of M4 scope
  here).

  5. bots/slack.py (M4)
  - async def post_reply(channel, thread_ts, answer, sources) and
  post_text(channel, thread_ts, text) via chat.postMessage (httpx +
  settings.SLACK_BOT_TOKEN), Block Kit: answer section + sources context block
